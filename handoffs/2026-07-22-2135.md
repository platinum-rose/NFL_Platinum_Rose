## Known Limitations / Follow-up

1. The beat splitter is now much better at matchup separation, but it is still deterministic transcript parsing. Continue reviewing reports for:
   - incorrect inferred matchup when a historical comparison is phrased like a current matchup;
   - spread side flips when the transcript says `against` near the opponent;
   - single-team context that should be attached to a prior matchup.
2. Current-market coverage only exists where `data/sportsbooks/nfl-week1-lines-2026.json` has a matching game. Most reports show `No current public-line snapshot loaded for this matchup.`
3. The OddsChecker snapshot is manually stored. If this becomes production workflow, add a deliberate timestamped line-ingestion path rather than live scraping from the report builder.
4. Existing host summaries still lack `source_timestamp` unless host-summary extraction is rerun from timestamped/diarized transcript segments. Do not overwrite host summaries without an explicit timestamp-backfill plan.
5. Some early non-matchup sections in episode reports are still low value. Consider hiding or collapsing generic intro/setup beats by default.
