NFL Dashboard (Platinum Rose) — Audit Report

Audit date: 2026-07-07 · Auditor: Claude (Fable), full-codebase audit per Fable_Project_Audit_Prompt

Executive summary

NFL Platinum Rose is a well-run project that has already fixed its scariest historical problem — API keys in the public browser bundle — with a clean server-side proxy pattern, and it shows strong engineering hygiene (centralized API config, a localStorage key catalog with permanence levels, receipts on agent runs, an anti-patterns doc). The most significant open issue is a guardrail one: the Obsidian→Supabase vault sync copies note content into a cloud table readable by betting partners without checking sensitivity tiers, so a mis-filed or unlabeled note would be exported when the fail-safe rule says it must not be. The biggest structural facts to plan around: all automation (19 workflows) runs on GitHub Actions' cloud scheduler, the app is hosted on public GitHub Pages, and "critical" user-entered picks live in browser localStorage. None of these are wrong today; all three should be staged toward owned infrastructure as the project matures.

Data ownership & vendor lock-in [Data-Ownership]

Formats are healthy everywhere: public/*.json in the repo (plain JSON), Supabase (open Postgres), vault notes (markdown), nflverse (open CSVs). The exposures are locational, not format: GitHub — repo, hosting, automation, and secrets all in one provider; if the account were locked tomorrow, code survives in local clones but the site, the robots, and their secrets all stop at once (plain language: eggs, basket). Supabase — same story and same fix as Rosie: a scheduled dump makes this migration-pain instead of data-loss. Browser localStorage — the one place user-entered data lives outside your control perimeter entirely (Finding 4). TheOddsAPI/ESPN — feeds, not custodians; nothing of yours is stored there. Identity: GitHub login and Supabase auth; no Google/Apple sign-in dependencies found.

Evolution roadmap

  1. Add sensitivity-tier filtering to the vault→Supabase export (high, small diff). (Finding 1) Plain language: teach the copying machine to read privacy labels before it copies — and to treat unlabeled notes as private, per the house rule.
  2. [Data-Ownership] Move critical-permanence localStorage keys into Supabase with local cache (med). (Finding 4) Plain language: your hand-entered picks deserve the same database the odds get.
  3. Fix CLAUDE.md's env documentation to match the proxy architecture (med, 10 minutes). (Finding 3) Plain language: correct the manual before it teaches someone to re-open a fixed security hole.
  4. [Local-First] Package the agents as systemd timers on M6 alongside their GHA twins (med — mostly packaging). (Finding 2) Plain language: give the robots a bedroom at home, even if they keep working from GitHub's office most days.
  5. [Data-Ownership] Nightly Supabase pg_dump — combine with Rosie's backup job (do now, cheap). Plain language: one backup habit covers both family projects.
  6. [Local-First] Swap podcast transcription priority-1 to local whisper.cpp — the rare local-AI move that's practical on today's hardware (optional, do when convenient). Plain language: turning podcasts into text is the one AI job your current computer can already do itself, free.
  7. Delete superseded v1 agents and the one-off test script; add the VITE_BYPASS_AUTH CI tripwire (low). (Findings 5–6)
